# Bhushan Games — Studio Website

Official website for **Bhushan Games**, an independent mobile game studio.
HTML5 + CSS3 + vanilla JavaScript. No React/Vue/Angular, no Bootstrap/Tailwind,
no dependencies, no build step required.

Built to scale to **100+ games**: adding a title means editing **one JavaScript
file**. Cards, filters, detail pages, sitemap entries and structured data all
generate themselves.

---

## Add a game (the only thing you normally do)

Open `js/games-data.js`, copy an existing object in the `GAMES` array, change
the values, save. That's it.

```js
{
  slug: 'my-new-game',                 // unique, url-safe
  title: 'My New Game',
  tagline: 'One short line.',
  shortDescription: 'One or two sentences for the card.',
  status: 'live',                      // 'live' | 'beta' | 'coming-soon'
  category: 'Puzzle',
  icon: '/images/games/my-new-game/icon.svg',
  playUrl: 'https://play.google.com/store/apps/details?id=…',
  featured: true                       // shows on the homepage
}
```

The new game immediately appears in:

| Where | How |
|---|---|
| Homepage featured row | if `featured: true` |
| `/games.html` grid | always, sorted by `featured` → `order` → title |
| Status filters | counts update; a new status adds its own button |
| `/game.html?slug=my-new-game` | full detail page, generated |
| `sitemap.xml` + `/games/<slug>/` | after `node tools/build.js` |

Every field, required and optional, is documented at the top of
`js/games-data.js`. Drop the game's art in `images/games/<slug>/`.

**No HTML file ever needs to be edited to add, remove or reorder a game.**

### Why templates.js is separate

The same functions that build a game card in the browser also build it in Node
during the static build. There is one implementation, so the live site and the
pre-rendered pages can never drift apart.

## Run it

```bash
cd bhushan-games
python3 -m http.server 8080
# http://localhost:8080
```

Use a server, not `file://` — asset paths are root-absolute (`/css/style.css`).

## Optional: static per-game pages (recommended before launch)

`/game.html?slug=…` renders client-side. That works, and Google executes
JavaScript, but link previews on WhatsApp, Slack, X and Facebook generally do
**not** — they read the raw HTML, so every game would share the same generic
preview card.

Fix it with one command:

```bash
node tools/build.js
```

This reads `js/games-data.js` and writes:

- `games/<slug>/index.html` — fully rendered, correct `<title>`, Open Graph,
  canonical and JSON-LD per game
- `sitemap.xml` — every page plus every game

Re-run it whenever you edit the catalogue. Both URL styles keep working; the
static ones are what you should share and submit to Search Console.

## Before you go live

| What | Where |
|---|---|
| Domain (`bborse.github.io`) | `js/site-config.js` → `origin`, plus the `<link rel="canonical">` and `og:url` tags in each HTML head, `robots.txt` |
| Google Play developer URL | `js/site-config.js` → `playDeveloperUrl` and the footer link |
| Play Store URL per game | `js/games-data.js` → `playUrl` |
| Real screenshots and icons | `images/games/<slug>/` — the current art is generated placeholder |
| Social handles | `js/site-config.js` → `socials` |
| Email addresses | `js/site-config.js` |

### Placeholder numbers you must replace

The rating (4.6 / 3,120), the 50K+ install counts and the studio stats on the
homepage and About page are **illustrative**. The rating also goes into
`schema.org` `aggregateRating` on the game page — Google treats invented review
markup as spam, so put your real Play Console figures in before launch, or
delete `rating` / `ratingCount` from the game object and the block disappears.

### Legal pages

`privacy-policy.html` and `terms.html` are complete drafts, not legal advice.
Each opens with an amber banner listing what to do:

- Fill in every `[bracketed placeholder]` (legal entity, address, retention
  periods, jurisdiction).
- Make the privacy data table match what your builds actually do — and match
  each game's Google Play **Data safety** form exactly.
- Have a lawyer review the liability, warranty and governing-law clauses.
- Delete the `.legal-notice` block on each page when done.

Google Play requires a reachable privacy policy URL before you can publish.

### Contact form

`contact.html` has no backend — it composes a `mailto:` link. To collect
submissions properly, give the `<form>` an `action` and `method` (Formspree,
Netlify Forms, Basin, or your own endpoint) and delete the submit handler in
`js/site.js` → `initContactForm`.

## What's included

**Pages** — home, catalogue, game detail, about, portfolio, contact, privacy,
terms.

**Components** — glassmorphism sticky navbar with auto-hide and mobile drawer,
dark mode toggle, page loader, animated blobs, game cards with per-game accent
colours, status badges (Live / Beta / Coming Soon), status filters, screenshot
slider with autoplay + swipe + keyboard + lightbox, click-to-load YouTube
facade, accordion, animated counters, timeline, scroll progress, back-to-top,
sticky mobile install bar, custom cursor, ripples, scroll reveal.

**Accessibility** — semantic landmarks, skip links, visible focus rings, ARIA on
every control, full keyboard support, lightbox focus trap, `prefers-reduced-motion`
disables all motion.

**SEO** — per-page title/description/canonical, Open Graph, Twitter cards,
schema.org (Organization, WebSite, SoftwareApplication per game, AboutPage,
ContactPage), sitemap, robots, manifest.

**Performance** — zero JS dependencies, deferred scripts, lazy images with
explicit dimensions, non-blocking fonts, YouTube loaded only on click.

### Minification (optional)

```bash
npx --yes esbuild css/style.css --minify --outfile=css/style.min.css
npx --yes esbuild js/site.js --minify --outfile=js/site.min.js
```

Enabling gzip/brotli on your host matters more than minifying.

## Regenerating placeholder art

The SVGs were produced by a throwaway script kept in the session scratchpad
(`gen_studio.py`), and the PNGs were rasterised from them with headless Chrome:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --window-size=1200,630 --default-background-color=00000000 \
  --screenshot=images/og-image.png "file://$PWD/images/og-image.svg"
```

Replace everything in `images/games/` with real store assets when you have them.
